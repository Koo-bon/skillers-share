# 질문 플로우

## 원칙

**주제를 묻지 않는다.** "뭘 발표하시겠어요"는 막막한 사람을 더 막히게 한다. 답하기 쉬운 것만 물어서 소재를 역산한다.

**질문은 보편적으로, 선택지는 개인 기록에서.** 질문 문구는 누구에게나 통해야 하고, 보기는 각자의 대화 기록 스캔 결과로 채운다.

**모든 문항에 탈출구가 있다.** `모르겠어요` 또는 `알아서`. 전부 넘겨도 끝까지 간다.

**사용자 개입은 총 5회.** 질문 3개 → 제목 고르기 → 목차 확인. 이보다 늘리지 않는다.

---

## ⓪ 스캔 (자동, 질문 아님)

`~/.claude/projects/` 아래 최근 6주치 대화를 훑는다. 찾을 것:

| 찾는 것 | 어떻게 | 쓰이는 곳 |
|---|---|---|
| 직접 만들거나 고친 스킬·도구 | `SKILL.md` 작성·수정, 새 디렉터리 생성 | Q1 보기 · 유형 추론 |
| 반복해서 쓴 스킬 | 스킬명 등장 횟수 | Q1 보기 · 유형 추론 |
| 여러 번 시도한 흔적 | 같은 목표를 3회 이상 다르게 시도 | Q1 보기 · 삽질기 소재 |
| 여러 스킬을 이어 쓴 구간 | 한 세션에 3개 이상 스킬 호출 | Q1 보기 · 작업 흐름 유형 |
| 만든 파일·배포 링크 | 생성된 파일 경로, 배포 URL | 데모 가능 여부 판단 |

각 후보에 **한 줄 근거**를 붙인다. 근거 없는 후보는 넣지 않는다.

```
spec-guard 직접 만든 것 — 6주간 40회 사용, 제작 과정이 기록에 남아 있음
```

기록이 빈약하면 그 사실을 먼저 말한다. **없는 걸 지어내지 않는다.**

### Q1 — 소재 (세 문항, 한 화면)

문항 문구는 고정. 보기만 스캔 결과로 채운다.

**1. 최근에 누가 "그거 어떻게 했어요?"라고 물어본 적 있나요?**
남이 물어본 것은 수요가 이미 검증된 주제다. 가장 확실한 신호.

**2. 요즘 설명할 때 유독 신나는 게 있나요?**
1시간을 버티게 하는 건 완성도가 아니라 화력이다.

**3. 최근 한 달, 시간을 제일 많이 쓴 일은?**
시간을 쓴 곳에 노하우가 쌓인다. 본인만 그걸 별거 아니라고 본다.

각 문항 보기:

```
① [스캔 결과 1 — 근거 한 줄]
② [스캔 결과 2 — 근거 한 줄]
③ 클로드 밖의 일이에요 (직접 입력)
④ 모르겠어요 — 내 대화 기록 보고 골라주세요
```

③이 필요한 이유 — 실제 공유회 중 `팔로워 100명만 되도 팬은 만들어집니다`, `파티룸 창업 무물보`, `메타 광고 쌩기초` 같은 본업 주제는 대화 기록에 잡히지 않는다.

**하나만 답해도 넘어간다.** 여럿이면 겹치는 지점을 잡는다 — 남이 물어봤고 + 내가 신나고 + 시간을 많이 쓴 것이 겹치면 그게 최적 주제다.

**④를 고르면 대화 기록 분석으로 넘어간다.** 스캔 결과 전체를 다시 훑어 아래 순서로 후보 3개를 추리고, 각각에 근거와 추천 이유를 붙여 제안한다.

| 순위 기준 | 왜 |
|---|---|
| 1. 대화량 | 오래 붙들고 있었다는 뜻이고, 그만큼 할 말이 있다 |
| 2. 완결성 | 끝까지 간 것이 발표하기 쉽다. 만든 파일·배포 링크가 있으면 가산 |
| 3. 이야기성 | 시도가 여러 번 반복됐거나 방향을 튼 흔적이 있으면 가산 (삽질기 소재) |

제안 형식:

```
대화 기록을 보니 이 셋이 발표거리입니다.

① spec-guard 직접 제작
   근거: 6주간 40회 사용, 제작 과정이 기록에 남아 있음
   추천 이유: 만든 것 + 쓴 기록이 둘 다 있어 데모까지 됩니다

② 슬랙 봇
   근거: 3번 시도 후 방향 전환
   추천 이유: 실패 과정이 그대로 남아 있어 삽질기로 강합니다

③ KV 파이프라인
   근거: 스킬 3개를 이어 쓴 세션 5회
   추천 이유: 흐름이 있어 따라 하기 좋습니다

이 중에 끌리는 게 있나요? 없으면 다시 훑겠습니다.
```

**여기까지 와서 빈손인 사람은 없어야 한다.** 스캔 결과도 비어 있으면 솔직히 말하고, 최근 작업을 두세 문장으로 적어달라고 요청한다. **지어내지 않는다.**

### Q2 — 대상

제목의 "대상"이 여기서 나온다. 좁을수록 잘 팔린다.

```
① 나와 같은 직무 (직무명 직접 입력)
② AI 처음 쓰는 사람
③ 쓰고는 있는데 더 잘하고 싶은 사람
④ 특정 업종·직업 (직접 입력 — 학원 원장, 1인 사업자 등)
⑤ 알아서 정해줘
```

⑤를 고르면 소재에서 역추론한다. 소재가 특정 직무의 문제를 푼 것이면 그 직무를, 범용 도구면 `쓰고는 있는데 더 잘하고 싶은 사람`을 기본값으로 한다.

### Q3 — 디자인 컨셉

```
① 미니멀 B&W — 흑백, 큰 여백, 텍스트 중심
② 볼드 컬러 — 단색 지배 + 초대형 타이포
③ 친근·소프트 — 둥근 폰트, 파스텔
④ 에디토리얼 — 풀블리드 이미지 + 세리프
⑤ 다크 테크 — 어두운 배경, 모노스페이스
⑥ 내가 원하는 레퍼런스가 있어요 (링크 또는 이미지)
⑦ 알아서 정해줘
```

⑥은 `themes.md` 의 커스텀 추출 절차를 따른다. ⑦은 `themes.md` 의 자동 매칭 표를 따른다.

## 안 묻고 추론하는 것

| 항목 | 근거 |
|---|---|
| 공유회 유형 | 소재 성격 (`types.md` 추론 규칙) |
| 청중이 가져갈 것 | 소재 + 대상 |
| 데모 여부 | 소재에 보여줄 실행물이 있는지 |
| 시간 배분 | 유형 + 데모 여부 (`timeline.md`) |

**목차 확인 단계에서 한 번에 보여주고 거기서 고친다.** 미리 묻지 않는다. 틀린 걸 고치는 게 빈칸을 채우는 것보다 쉽다.

---

## 목차 확인 단계에 보여줄 것

```
제목      [고른 것]
유형      [6종 중 하나] — 이렇게 판단한 이유 한 줄
대상      [Q2 답변]
가져갈 것 [추론 결과]
데모      있음/없음 — 이렇게 판단한 이유 한 줄
시간 배분 [timeline.md 표]
목차      슬라이드 제목 25~35개
```

**추론 항목에는 반드시 근거 한 줄을 붙인다.** 근거가 보여야 사용자가 틀린 걸 잡아낼 수 있다.
